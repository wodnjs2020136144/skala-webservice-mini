## A-2. 서비스 한 문장 ✅

> **[교대근무 병동의 간호사와 수간호사]** 가 **[오늘의 근무 배정과 인계를 확인해야 하는 상황에서]**
> **[자기 역할을 어디서 봐야 하는지, 인계를 제대로 받기는 했는지 알 수 없고, 배정이 바뀌면 여러 곳에 다시 알리고 최신본을 확인해야 해서]** 불편한데,
> 이 서비스로 **[누가 무엇을 맡고 무엇을 주고받았는지 확인하고, 그 기록을 남길 수 있다]**.

### 핵심 가치 한 줄

> **근무표가 끝나는 지점에서 시작한다.**
> 누가 나오는지까지만 말하는 근무표에, **그날의 역할과 인계를 붙여 한 줄로 잇는다.**

### 이 문장이 통과한 3가지

| 기준 | 어디서 |
|---|---|
| Actor 2명의 불편이 각각 있다 | 간호사 = 역할·인계 / 수간호사 = 배정 변경 전파 |
| F-02~F-05가 근거를 갖는다 | 아래 A-3 표에서 대응. **F-01은 기반 기능이라 Pain과 1:1로 두지 않는다** |
| 시간이 아니라 **구조** | "빠르게·짧은 시간"이 한 번도 안 나온다. 전부 *어디서 봐야 / 제대로 받았는지 / 어떻게 알려야* |

### ⚠️ 오늘 밤 한 군데만 조인다

`"오늘의 근무 배정"` 은 **분기 A·B 양쪽에서 참**이라 지금은 이대로 둔다. Q1 답이 나오면 한 번만 손댄다.

- **분기 A**(전날 확정 가능) → "근무 전에 확인해야 하는 상황에서"
- **분기 B**(당일 결정) → "배정이 바뀔 때마다 확인해야 하는 상황에서"

## A-3. Pain point ↔ Solution ✅

| # | Actor | Pain (현상 + 원인) | Solution (그 Actor가 할 수 있게 되는 것) | 연결 기능 |
|---|---|---|---|---|
| 1 | 간호사 | **[관찰]** 출근해서야 자기 역할을 안다 · **[D: Q1·Q2-c 확인]** 원인 — 근무표에는 근무조(D/E/N)만 있고 액팅·차지 역할은 병동에서 따로 정해지기 때문 | **근무와 같은 화면에서** 그날 자기 역할과 담당 환자를 확인한다 | F-02, F-03 |
| 2 | 간호사 | **[관찰]** 인계를 제대로 받았는지 확인할 방법이 없다 · **[D: Q2-b 확인]** 원인 — 무엇을 꼭 받아야 하는지 정해져 있지 않고, 받았다는 기록도 남지 않기 때문 | **역할에 맞는 필수 항목**으로 인계를 주고받고, **받는 사람이 핵심 내용을 자기 말로 정리해** 확인 처리한다 | F-04 |
| 3 | 수간호사 | **[관찰]** 결원이 생기면 **변경을 여러 곳에 다시 알려야 하고**, 최신 배정이 무엇인지도 누가 언제 왜 바꿨는지도 남지 않는다 · **[D: Q2-c 확인]** 원인 — 엑셀을 고치고 메신저로 재공지하는 방식이기 때문 | **화면에서 바로 재배정**하고, 바뀐 배정이 **당사자에게 그대로 보이며**, 변경 사유와 이력이 함께 남는다 | F-05 |

### 현재 후보 기능 5개 — **인터뷰 반증 시 조정한다**

| ID | 기능 | Actor |
|---|---|---|
| F-01 | 확정 근무 등록 | 수간호사 |
| F-02 | 날짜별 역할·담당 환자 배정 및 게시 | 수간호사 |
| F-03 | 내 배정·변경 확인 | 간호사 |
| F-04 | 구조화 인계 작성 + 수신자 요약 확인 | 간호사 |
| F-05 | 결원 시 재배정 + 변경 이력 기록 | 수간호사 |

**완료 판정**: Pain 3개가 전부 F-02~F-05에 연결됨 ✅

> ⚠️ **"바꾸지 않는다"가 아니다.** `docs/05` §3-1의 `(x)` 대응(x1~x3)이 기능 조정을 전제로 한다.
> 예: Q2-b에서 *"이미 확인 기록이 남는다"* 가 나오면 **F-04의 범위가 줄어든다.**
> **오늘 기준 후보이고, 인터뷰 반증이 나오면 조정한다.**

### ⚠️ 용어 하나만 절대 흔들리면 안 된다

`receiver_summary` = **받는 사람이 핵심 내용을 자기 말로 요약하는 것**이다. "수신자가 누군지 기록"이 아니다.
I-PASS의 `Synthesis by receiver` 근거가 여기 걸려 있고, 단순 ack(`received_at`)과 read-back을 가르는 지점이다.
**이 표현이 흔들리면 API 필드명과 DBML까지 번진다.**

## A-4. 하지 않는 것 (Out of scope) ✅

1. **근무표 자동 생성** — B2B 6종 레드오션 + NP-hard, solver 영역
2. **실제 EMR 연동** — 데모는 가상 입원 건 수동 등록 (`docs/03` §8-2)
3. **실제 환자 개인정보** — 가상 데이터만 사용, 식별은 병상번호 + `patient_ref_code` 까지
4. **임상적 판단·추천** — 중요도 자동 정렬, 위험 예측
5. **교육 일정·급여·알람** — 기술서 8장 "향후 개선 사항"으로

> 추가하고 싶은 게 생기면 **여기 적고 기능 목록에는 넣지 않는다.**

- 조사일: 2026-09-15
- 목적: 미니프로젝트 주제 확정 전, **무엇이 이미 해결됐고 무엇이 비어 있는지**를 확인한다.
- 원칙: 확인된 1차 출처만 기재. 확인 못 한 항목은 `확인 불가`로 표기.

## 1. 말한 불편을 '문제'로 재정의한다

들은 이야기를 그대로 쓰면 6개의 별개 서비스가 된다. **원인 계층으로 쪼개면 3덩어리**로 정리된다.

| # | 원문 불편 | 진짜 원인 | 계층 |
|---|---|---|---|
| 1 | 액팅·차지 배정을 출근해서야 안다 | 듀티표에는 **근무조(D/E/N)만** 있고 **당일 역할 배정**은 병동 화이트보드·구두로 결정됨 | **정보 전달** |
| 2 | 팀장이 한 명 이탈 시 스케줄 재조정이 힘듦 | 근무표 **확정 이후의 변경**은 시스템 밖(엑셀 수정 + 메신저 재공지) | **변경 관리** |
| 3 | 교대마다 알람을 다시 맞춰야 함 | 알람 앱이 **근무 데이터와 연결되어 있지 않음** | 정보 전달(파생) |
| 4 | 듣고 싶은 교육이 있는데 듀티와 안 맞음 | 교육 일정과 근무 일정이 **다른 시스템**에 있고, 스케줄 생성 시 교육이 제약조건에 없음 | **변경 관리** |
| 5 | 인수인계 내용이 차지/액팅별로 비중이 달라 스트레스 | 인수인계가 **비구조화 + 역할별 뷰 없음** | **지식 전달** |
| 6 | 오프에도 병원 카톡을 봄 | 공지·근무변경·인수인계가 전부 **카톡 한 채널**로 쏟아짐 | 정보 전달(결과) |

> **핵심 관찰**: 6개 중 5개가 "듀티표가 근무조까지만 말하고, 그 다음(역할·변경·교육·인계)은 시스템 밖 카톡으로 흐른다"는 **하나의 단절**에서 파생된다.
> 6번(오프 중 카톡)은 독립 문제가 아니라 **1·2·4·5가 해결되지 않아 생긴 증상**이다.

### 왜 비어 있는가 (중요 — '설계 고민' 슬라이드 재료)

- **인수인계**는 환자 식별정보를 다루므로 **EMR 영역**이다. B2C 앱은 법적으로 못 건드리고, EMR 벤더는 이걸 별도 UX로 풀지 않는다. **그 사이가 통째로 비어 있다.**
- 현장 증언: *"EMR 시스템을 쓰면서 기록들을 또 다 수기로 옮겨서 적고 그렇게 인계를 했던 경험이 있는데"*
- 국내 연구는 이미 많다 — SBAR 기반 인수인계 표준항목 개발, 국내병원 간호사 인수인계 실무표준·표준지침 개발, **간호사의 서면 인수인계 오류 경험** 연구 등. **수요는 논문으로만 존재하고 제품은 없다.**

## 5. 파편화가 만드는 불편 (직접 물어보면 확인될 지점)

확정 근무 하나가 지금 **최소 5개 채널**로 흩어진다.

```
수간호사 엑셀  →  카톡 단톡방 공지  →  개인이 마이듀티에 손으로 재입력
                        ↓                        ↓
                  변경 요청도 카톡          알람은 폰 기본 시계에 또 따로
                        ↓
              당일 역할(차지/액팅)은 병동 화이트보드
                        ↓
                인계는 종이 노트 / EMR 수기 전사
                        ↓
                교육은 KNA 에듀센터에서 따로 신청
```

여기서 나오는 구체적 손실:

1. **이중 입력** — 확정 표를 개인이 다시 타이핑. 오타 나면 오프에 출근한다.
2. **단일 진실 부재** — 카톡 마지막 메시지가 최신인지 아무도 확신 못 함.
3. **역할 정보의 소실** — 근무조는 남지만 "그날 내가 차지였는지"는 어디에도 기록되지 않음 → 경력 증빙·업무량 분석 불가.
4. **알람 재설정 노동** — 듀티가 앱에 있는데 알람은 사람이 다시 맞춤.
5. **오프 침범** — 위 전부가 카톡으로 오므로 **오프에도 카톡을 봐야만 안전**해짐. 6번 불편의 진짜 원인.

## 6. AI를 쓴다면 — 되는 것과 안 되는 것

### ❌ LLM으로 근무표를 직접 생성하면 안 된다 (실증 근거 있음)

- **Nurse Rostering Problem은 NP-hard**로 확립된 조합최적화 문제다.
- arXiv **"Formalize, Don't Optimize: The Heuristic Trap in LLM-Generated Combinatorial Solvers"** — 프론티어 LLM 3종 × 4,577개 인스턴스 실험:
  - **"Python + OR-Tools attains the highest correctness on every LLM"** — LLM이 모델링만 하고 검증된 solver가 풀 때 정확도 최고
  - LLM에게 직접 탐색을 시키면 **heuristic trap** 발생: 속도 이득 1.03~1.12배로 미미한데 **어려운 문제일수록 정확도 급락**
- 실제 상용 제품도 같은 구조다. **Lightning Bolt**는 자사를 "combinatorial optimization"이라고 명시하고, **DutyMate(.kr)·듀티플래너**는 AI가 **초안·품질점검**만 하고 확정은 사람이 하는 human-in-the-loop이다.

### ✅ 올바른 아키텍처

```
LLM (자연어 제약 → 형식 모델)  →  CP-SAT / MIP solver (해 도출)  →  LLM (결과 설명)
```

| 위치 | AI가 하는 일 | 이 프로젝트에서의 화면 |
|---|---|---|
| 입력단 | "주말은 격주로, 나이트 3연속 금지" 같은 **자연어 병동 규칙 → 제약식 변환** | 병동 규칙 설정 화면 |
| 해결단 | **solver 담당** (OR-Tools CP-SAT). AI 아님 | 근무표 생성 |
| 설명단 | **"왜 내가 이 나이트에 배정됐는지"** 설명, 변경 시 영향도 요약 | 근무표 상세 |
| 지식단 | **비구조화 인계 메모 → SBAR/I-PASS 구조로 정규화·요약**, 역할별(차지/액팅) 중요도 재배열 | 인수인계 작성·조회 |

### 인수인계 AI의 국제 레퍼런스 (있으면 발표가 강해진다)

- **표준 프로토콜**: **SBAR** (Situation-Background-Assessment-Recommendation, Kaiser Permanente 2003, 원류는 미 해군 잠수함 교대) / **I-PASS** (Illness severity, Patient summary, Action list, **Situation awareness & contingency plans**, **Synthesis by receiver**)
  - I-PASS 대표 연구: 의료오류 **24.5 → 18.8건/100입원**, 예방가능 유해사건 **4.7 → 3.3건**. (단 AHRQ는 **외부 재현 결과가 비일관**이라고 명시)
- **인수인계 실패의 대가**: Joint Commission Sentinel Event Alert 58 — 커뮤니케이션 실패가 **의료과실 소송의 최소 30%**에 책임, 5년간 **1,744명 사망**, **17억 달러** 비용.
- **AI 제품 현황**: **Epic "Art"** — 교대 종료 시 care plan note 자동 생성, Mercy Health 기준 **노트당 3.5분 → 32초(85% 감소)**, 정시 완결 노트 **225% 증가**, 간호사 검토·서명 필수. Mount Sinai가 2026년 7월 **Chart with Art**를 간호에 확대.
- **그런데 갭이 남아 있다**: 앰비언트 AI는 **"문서화 부담 감소"**에 최적화돼 있지, **SBAR/I-PASS 구조에 정렬된 인수인계 전용 AI는 확인되지 않는다.** 특히 Joint Commission이 요구하는 **contingency plan**과 **수신자 복창 검증**을 구조적으로 강제하는 제품은 미확인.

### 수면·건강을 스케줄에 넣는 것도 비어 있다

- 근거는 이미 명확하다: **정방향 회전(D→E→N)이 역방향보다 우월** — 야간 종료 시 "매우 높은 피로" 보고가 **정방향 63.7% vs 역방향 93.7%** (JAMA Network Open). 연속 야간 5회 이하 권장(Cleveland Clinic). 낮잠은 15~30분, 1시간 기상은 수면관성 위험(NIOSH).
- **그런데 이걸 rostering의 soft constraint로 넣는 상용 제품은 확인되지 않는다.** Timeshifter(NASA 기반 알고리즘, Harvard Dr. Lockley)는 **이미 짜인 표에 사후 대응**할 뿐 생성 단계에 개입하지 않는다.

### ✅ 노릴 것 — 공백 3곳

1. **인수인계 (최대 공백)** — 20개 서비스 O 0개. 하루 30분 오버타임의 원인. 국제 표준(SBAR/I-PASS)이 이미 있어서 **데이터 모델을 설계할 근거가 풍부하다.**
2. **당일 역할 배정 (차지/액팅)** — 어떤 서비스도 데이터 모델에 없음. **직접 관찰한 1번 불편과 정확히 일치.**
3. **확정 이후의 변경 관리** — 근무 교환·결원 대체가 아직도 카톡. B2B는 "생성"까지만 하고 손을 뗀다.

> **이 셋은 원래 하나로 이어져 있다.**
> `근무조가 정해지고 → 그날의 역할이 배정되고 → 그 역할에 맞는 인계를 받고 → 누가 빠지면 역할까지 같이 재배정된다`
> 어떤 서비스도 이 한 줄을 갖고 있지 않다. **두 섬 사이의 다리가 비어 있다.**

## 8. 3일 프로젝트용 스코프 후보

### 후보 A — 병동 근무·역할·인계 통합 보드 ⭐ 추천

> "근무표는 **누가 나오는지**까지만 말한다. **그날 무엇을 맡고 무엇을 인계받는지**는 여전히 화이트보드와 카톡에 있다."

- **Actor**: 수간호사(배정자) / 간호사(수행자) — 2명. 관리자는 두지 않음
- **핵심 흐름**: 확정 근무 등록 → **일자별 역할 배정(차지/액팅/담당 구역)** → 근무 전 내 역할·인계 확인 → 교대 시 **구조화 인계 작성(SBAR 템플릿)** → **역할별 중요도로 재정렬된 인계 열람** → 결원 발생 시 역할 재배정
- **AI 지점**: 비구조화 인계 메모 → SBAR 구조 정규화 / 역할(차지 vs 액팅)에 따른 인계 항목 우선순위 재배열 / 미인계 항목 경고
- **평가**: Actor 2 ✅ / 화면 11~12 ✅ / 엔티티 8~9 ✅ / 외부연동 불필요 ✅ / 배경 근거 최상 ✅
- **설계 고민 재료**: 환자 식별정보를 어디까지 담을 것인가(가명처리·병상번호 기반), 인계 이력의 감사 추적, 복창 확인(read-back) 모델링

### 후보 B — 근무 교환·결원 대체 마켓

> "확정된 근무가 바뀌는 순간, 시스템이 끝나고 카톡이 시작된다."

- **Actor**: 간호사(요청/응답) / 수간호사(승인) — 2명
- **핵심 흐름**: 교환 요청 등록 → **규칙 위반 자동 검증**(나이트 3연속, 연속근무 5일, 11시간 휴식) → 가능한 상대 후보 제시 → 상호 수락 → 관리자 승인 → 확정 반영·이력
- **AI 지점**: 교환 성사 가능성 예측, 교환이 팀 전체 공정성에 미치는 영향 요약
- **평가**: Actor 2 ✅ / 화면 9~10 △ / 엔티티 6~7 ✅ / **규칙 검증 로직이 명확해 설계가 깔끔** ✅ / 차별점은 A보다 약함(널스데이·DutyMate.kr이 일부 함)

### 후보 C — 교대근무 연동 직무교육 신청

> "교육은 KNA 에듀센터에, 근무는 병동 엑셀에 있다. 둘은 만난 적이 없다."

- **Actor**: 간호사 / 교육담당자 — 2명
- **핵심 흐름**: 교육 개설 → 간호사의 듀티 기반 **수강 가능 회차 자동 필터링** → 신청 → 근무 변경 시 충돌 알림·대체 회차 추천 → 이수 평점 누적
- **평가**: 완전 미개척 ✅ / 화면 8~9 △ / **엔티티가 얇다(5~6개)** ❌ / 배경 근거는 있으나 A만큼 절실하지 않음 △

### 판단

**A를 권한다.** 이유 셋:

1. **직접 관찰한 불편(1번, 5번)과 정확히 일치**한다 → 배경 슬라이드에 "겪은 사람의 말"을 넣을 수 있다. 세부 평가기준의 *"구체적인 문제 정의(원인·배경·현황 포함)"* 를 정면으로 충족.
2. **커버리지 매트릭스에서 O가 0인 두 열(인수인계 + 역할 배정)을 동시에 차지**한다 → "왜 이걸 만드는가"가 자동으로 설명된다.
3. **데이터 모델이 풍부하고 자연스럽다** — 근무배정·역할·인계·인계항목·확인이력이 전부 관계를 갖는다. 40점짜리 시스템 설계에서 쓸 게 많다.

B는 A의 **"결원 발생 시 재배정"** 흐름에 축소해서 흡수시키면 된다. C는 Appendix의 향후 확장으로 넣는다.

- 목적: 주제 확정 전, **무엇이 이미 해결됐고 무엇이 비어 있는지** 확인한다.

## 0. 출처 등급 — v2에서 신설

v1은 "1차 출처만 기재"라고 선언했으나 실제로는 언론·업체 블로그·제품 홍보자료가 섞여 있었다. 삭제하지 않고 **등급을 붙인다.**

| 등급 | 범위 | 신뢰 수준 |
|---|---|---|
| **A** | 법령·정부·학회·학술논문 | 발표에서 단정해도 됨 |
| **B** | 제품 공식 홈페이지·앱스토어 설명 | 사실이되 **판매자 주장** 포함 |
| **C** | 언론 기사·업체 블로그·위키 | 방향은 신뢰, 수치는 재확인 필요 |
| **D** | 현장 인터뷰·검증 전 가설 | **아직 근거가 아님.** 확인 대상 |

> 원칙: **A·B는 단정문, C는 "~에 따르면", D는 "~인지 확인 필요"로 쓴다.**

## 1. 말한 불편을 '문제'로 재정의한다

| # | 원문 불편 | 진짜 원인 | 계층 |
|---|---|---|---|
| 1 | 액팅·차지 배정을 출근해서야 안다 | 듀티표에는 **근무조(D/E/N)만** 있고 당일 역할은 화이트보드·구두 | **정보 전달** |
| 2 | 팀장이 한 명 이탈 시 재조정이 힘듦 | 근무표 **확정 이후 변경**은 시스템 밖 | **변경 관리** |
| 3 | 교대마다 알람을 다시 맞춰야 함 | **확정 근무표가 개인 앱에 자동으로 들어오지 않아** 수동 입력이 선행됨 | 정보 전달(파생) |
| 4 | 교육이 듀티와 안 맞음 | 교육과 근무가 다른 시스템. 스케줄 생성 시 교육이 제약조건에 없음 | **변경 관리** |
| 5 | 인계 비중이 차지/액팅별로 달라 스트레스 | 인계가 **비구조화 + 역할별 뷰 없음** | **지식 전달** |
| 6 | 오프에도 병원 카톡을 봄 | 공지·근무변경·인계가 전부 카톡 한 채널로 | 정보 전달(결과) |

> 6번은 독립 문제가 아니라 **1·2·4·5가 안 풀려서 생긴 증상**이다.
> ⚠️ **3번 수정(v2)**: v1은 "알람 앱이 근무 데이터와 연결 안 됨"이라고 썼으나 **틀렸다.** 마이듀티는 근무 종류별 알람 시간을 설정하면 그 근무를 달력에 저장할 때 자동으로 울린다 — *"You no longer need to set the alarm separately every day according to your shift!"* [B]
> 실제 병목은 알람이 아니라 **확정 근무표를 개인이 손으로 다시 입력해야 한다**는 앞단이다.

## 2. 문제의 크기 — 배경 슬라이드 근거

### 2-1. 이탈 규모 [C — 대한간호협회가 병원간호사회 조사를 재분석해 언론에 배포]

| 지표 | 수치 |
|---|---|
| 병원 간호사 사직률 | 2020년 14.5% → 2021년 15.8% → **2022년 16.0%** |
| 사직자 중 5년 이내 경력 | **80.6%** (1년 미만 43.4% / 1~3년 20.5% / 3~5년 16.7%) |
| 신규간호사 1년 이내 사직률 | 2018년 42.7% → **2022년 57.4%** |
| 사직 사유 | 과다 업무·부적응 **20.8%** / 타병원 이동 14.4% / 질병 11.2% / 타직종 전환 10.8% / **교대·야간근무 6.3%** |

### ★ 인과를 단정하지 않는다 (v2 수정)

v1은 이렇게 썼다 — *"부적응의 상당 부분이 당일 역할을 모른 채 출근하고 비구조화된 인계를 받는 데서 온다."*
**이건 조사로 입증되지 않았다.** 사직 사유 조사는 "업무 과다·부적응"까지만 말하고 그 내부를 쪼개지 않는다.

**말할 수 있는 범위 [A/C]**

> 초년차 이탈이 80.6%로 크고, 그 1순위 사유가 업무 부적응(20.8%)이다.

**아직 가설인 범위 [D — 인터뷰로 확인]**

> 당일 역할 불확실성과 비구조화 인계가 그 부적응 경험에 **얼마나** 기여하는지는 확인되지 않았다.

### ★ 서비스 목표를 방어 가능한 지표로 잡는다

"이직률 감소"는 입증 불가능한 목표다. 대신 **서비스가 직접 움직이는 것**을 목표로 둔다.

| 목표 지표 | 현재(가설, 인터뷰로 측정) | 서비스가 바꾸는 방식 |
|---|---|---|
| 당일 역할 확인에 걸리는 시간 | 출근 후 확인 | 근무 전 앱에서 확인 |
| 인계 필수 항목 누락 건수 | 측정 안 됨 | 체크리스트 + 수신 확인 |
| 근무 변경 재공지 횟수 | 카톡 N회 | 보드 1곳에서 갱신 |
| 오프 중 확인 필요성 | 상시 | 변경 시에만 알림 |

### 2-2. 근무 실태 [C — 주간경향]

| 지표 | 수치 |
|---|---|
| 간호사 연간 노동시간 | 2,436시간 (2019) |
| 나이트 근무자 실제 근무 | 하루 평균 **13.1시간** (D 9.7 / E 9.1) |
| 초과근무 | 2019년 조사에서 **50.9%가 45~120분** |
| 구조적 원인 | **"못해도 하루에 30분씩은 오버타임이 발생하는 구조"** — 인수인계 |
| 정시 식사 불가 | 병동 간호사 **93%** |
| 기피 패턴 | **나오데(N→OFF→D)** "버려야 하는 오프", 더블듀티(16시간) |

> **"인수인계가 하루 30분 오버타임의 원인"** 은 이 프로젝트의 가장 강한 배경 문장이다. 단 **[C]** 이므로 *"2021년 주간경향 보도에 따르면"* 을 붙인다.

### 2-3. 근무표 작성자 [C]

- 작성 방식은 **여전히 엑셀 수기 / 화이트보드**가 광범위
- 48베드 병동 기준 **월 8~12시간** 소요, 자동화 시 2시간 이내
- 확정 후 변경은 **"관리자가 엑셀을 수정하고 메신저로 재공지"**
- **EMR ↔ 근태는 분리 운영이 표준** — "별도 입력하는 이중 작업"

### 2-4. 교육 [A/C]

- 의료법상 **연 8평점 이상 보수교육 의무**, 3년마다 면허신고. 운영은 **KNA 에듀센터**라는 별도 포털 [A]
- 조사한 근무표 자동생성 엔진 6종 중 **교육 일정을 제약조건에 넣는 곳은 확인되지 않음** [B]

### 4-2. ★ 해외에는 이미 있다 (v2 신설 — v1의 최대 오류 정정)

v1은 *"SBAR/I-PASS 구조에 정렬된 인수인계 전용 AI는 확인되지 않는다"* 와 *"역할 배정을 데이터 모델에 가진 서비스가 없다"* 고 썼다. **둘 다 글로벌 기준으로는 틀렸다.**

| 제품 | 실제로 하는 일 | 근거 |
|---|---|---|
| **Epic "Art"** | ① 차트 데이터로 **교대 종료 노트 AI 생성** (Mayo Clinic 기준 85% 단축) ② **"Assign Available Nurses"** — **환자 업무량·간호사 비율·진료 지속성·간호사 기술을 고려한 환자 배정 제안 자동 생성** | [B] epic.com/software/art |
| **ShiftSBAR** | 음성·텍스트 입력 → **Whisper 음성인식 + Claude로 SBAR 4개 섹션 자동 파싱**, 중요 검사결과·긴급 변화 자동 플래그, 서명 블록 포함 PDF 내보내기. 계정 불필요 B2C | [B] shiftsbar.com |

**그래서 차별점 주장을 이렇게 좁힌다.**

> ❌ (v1) "인수인계·역할 배정 제품이 세상에 없다"
> ✅ (v2) **"조사한 국내 공개 제품 중, 확정 근무 → 당일 역할 → 구조화 인계 → 결원 재배정을 하나의 흐름으로 연결한 사례는 확인하지 못했다."**

- Epic Art는 **미국 EHR 내장 기능**이라 국내 병동이 쓸 수 있는 선택지가 아니다. 다만 **"배정 제안"이라는 문제 자체는 이미 풀린 문제**임을 알고 있어야 한다
- ShiftSBAR는 **개인이 혼자 쓰는 변환 도구**다. 병동 단위 배정·수신 확인·이력이 없다
- 발표에서 이 둘을 **먼저 언급하고 차이를 말하면** 조사의 깊이가 드러난다. 모르고 "없다"고 하면 질문 한 번에 무너진다

### 4-3. 왜 국내에 비어 있는가 (v2 — 법적 단정 완화)

v1은 *"B2C 앱은 법적으로 못 건드린다"* 고 썼다. **부정확하다.**

- 건강정보는 **개인정보보호법 제23조 민감정보**로 처리가 원칙적으로 제한되지만, **별도 동의 또는 법령 근거가 있으면 처리 가능**하다 [A]
- 진짜 장벽은 "불가능"이 아니라 **비용**이다 — 별도 동의 설계, 접근 통제, 보안 요구수준, **병원 승인 절차**, EMR 연동 책임
- 그래서 개인 개발사 규모로는 진입이 어렵고, EMR 벤더는 이걸 별도 UX로 풀 유인이 약하다. **그 사이가 국내에서 비어 있다**
- ⚠️ **이 프로젝트는 실제 환자 개인정보를 사용하지 않고 가상 데이터만 쓴다**는 것을 기술서에 명시한다

## 5. 파편화가 만드는 불편

확정 근무 하나가 지금 여러 채널로 흩어진다.

```
수간호사 엑셀 → 카톡 공지 → 개인이 마이듀티에 손으로 재입력 → (여기서부터는 앱이 알람까지 자동)
                   ↓
             변경 요청도 카톡
                   ↓
       당일 역할(차지/액팅)은 병동 화이트보드
                   ↓
         인계는 종이 노트 / EMR 수기 전사
                   ↓
         교육은 KNA 에듀센터에서 따로 신청
```

1. **이중 입력** — 확정 표를 개인이 다시 타이핑. 오타 나면 오프에 출근한다. ← **여기가 진짜 병목**
2. **단일 진실 부재** — 카톡 마지막 메시지가 최신인지 확신 못 함
3. **역할 정보 소실** — "그날 내가 차지였는지"가 어디에도 기록되지 않음 → 경력 증빙·업무량 분석 불가
4. **오프 침범** — 위 전부가 카톡으로 오므로 오프에도 봐야 안전해짐

## 6. AI를 쓴다면 — 되는 것과 안 되는 것

### ❌ LLM으로 근무표를 직접 생성하면 안 된다 [A]

- **Nurse Rostering Problem은 NP-hard** 조합최적화다
- arXiv **"Formalize, Don't Optimize"** — LLM 3종 × 4,577 인스턴스 실험에서 **"Python + OR-Tools attains the highest correctness on every LLM"**. LLM에 직접 탐색을 시키면 **heuristic trap**: 속도 이득 1.03~1.12배인데 어려운 문제일수록 정확도 급락
- 상용 제품도 같은 구조다 — **Lightning Bolt**는 자사를 "combinatorial optimization"이라 명시, **DutyMate(.kr)·듀티플래너**는 AI가 초안·품질점검만 하고 확정은 사람이 한다

### ✅ 올바른 아키텍처

```
LLM(자연어 제약 → 형식 모델) → CP-SAT / MIP(해 도출) → LLM(결과 설명)
```

### ★ 이번 프로젝트에서 AI를 쓸 범위 (v2 — 축소)

| 쓴다 ✅ | 쓰지 않는다 ❌ |
|---|---|
| 자유 메모 → **SBAR 4개 섹션 초안 구조화** | **임상 중요도 판단** |
| **필수 항목 누락 표시** (템플릿 대비 빈칸 검출 = 규칙 기반) | 인계 항목 **자동 우선순위 결정** |
| 근무 변경 시 영향 요약 | 근무표 자동 생성 |

**왜 임상 판단을 빼는가** — 근거 셋:

1. **평가상 필요 없다.** 운영 가이드가 "AI 기능이 없는 경우"를 감점 사유가 아니라고 명시했다
2. **근거를 댈 수 없다.** 3일 안에 임상 중요도 기준을 세울 방법이 없고, 발표에서 "그 우선순위 근거가 뭐냐"는 질문에 답이 없다
3. **이미 있는 제품과 겹친다.** ShiftSBAR가 정확히 "긴급 상태 변화 자동 플래그"를 한다. 따라 하면서 근거는 더 약한 상태가 된다

### 인수인계 표준 [A]

- **SBAR** (Situation-Background-Assessment-Recommendation, Kaiser Permanente 2003)
- **I-PASS** (Illness severity / Patient summary / Action list / **Situation awareness & contingency plans** / **Synthesis by receiver**)
- **Joint Commission SEA 58** — 커뮤니케이션 실패가 의료과실 소송의 최소 30%에 책임, 5년간 1,744명 사망, 17억 달러

> ⚠️ **I-PASS 수치 인용 시 적용 범위를 반드시 표시한다 (v2 수정).**
> 의료오류 24.5 → 18.8건/100입원이라는 대표 연구는 **9개 소아과 전공의 프로그램에 적용한 핸드오프 번들 전체(교육·체크리스트·구두 인계·관찰 피드백)의 결과**이지, 한국 병동 간호사에게 템플릿 하나를 준 결과가 아니다. AHRQ도 **외부 재현 결과가 비일관**이라고 명시했다.
> **맞는 표현**: *"I-PASS는 구조화 인계의 설계 근거로 쓴다. 연구 효과 수치를 국내 간호병동의 예상 효과로 환산하지는 않는다."*

## 7. 결론 — 들어가면 안 되는 곳 / 들어갈 곳

### 🚫 피할 것

근무표 자동 생성(B2B 6종 경쟁 + 병원 도입 사례) / 듀티 공유·기록(마이듀티 선점) / **교대 알람(이미 근무 연동까지 구현됨)** / 커뮤니티(너스케입 선점)

### ✅ 노릴 것 — 국내 공백 3곳

1. **인수인계** — 국내 조사 대상 중 확인 안 됨. 하루 30분 오버타임의 원인 [C]. 국제 표준(SBAR)이 있어 **데이터 모델 근거가 풍부**하다
2. **당일 역할 배정(차지/액팅)** — 국내 조사 대상 중 확인 안 됨. **직접 관찰한 불편 1번과 일치**
3. **확정 이후의 변경 관리** — 근무 교환·결원 대체가 아직 카톡. B2B는 "생성"까지만 하고 손을 뗀다

> **이 셋은 원래 하나로 이어져 있다.**
> `근무조 확정 → 그날의 역할 배정 → 그 역할에 맞는 인계 → 누가 빠지면 역할까지 재배정`
> **국내에서 이 한 줄을 가진 서비스는 확인하지 못했다.**

## 8. 후보 A-lite — 3일 스코프 확정안 (v2)

v1의 후보 A는 근무 등록 + 역할 배정 + 환자 인계 + AI 요약 + 역할별 우선순위 + 누락 경고 + 결원 재배정까지 포함해 **3일 설계로는 넓었다.** 아래로 좁힌다.

> **수간호사가 확정 근무표에 당일 역할과 담당 구역을 배정하고, 간호사가 출근 전에 이를 확인하며, 교대 시 구조화된 인계 체크리스트를 전달·확인하는 병동 운영 보드**

### 핵심 기능 5개

1. **확정 근무 등록** (수간호사)
2. **날짜별 역할·담당 구역 배정 및 게시**
3. **간호사의 출근 전 배정 확인**
4. **구조화 인계 작성 + 수신 확인(read-back)**
5. **결원 발생 시 재배정 + 변경 이력 기록**

### ★ 역할별 인계는 살린다 — 단 AI가 아니라 규칙으로

리뷰는 "역할별 우선순위"를 통째로 빼라고 했지만, **그러면 관찰한 불편 5번이 사라진다.** 대신 방식을 바꾼다.

- ❌ AI가 인계 항목의 임상 중요도를 판단해 정렬
- ✅ **수간호사가 역할별 필수 인계 항목 세트를 미리 정의**하고, 그 역할로 배정된 사람에게 해당 체크리스트가 뜬다

이러면 **임상 판단이 사라지고 데이터 모델은 오히려 풍부해진다** — `역할 유형 ↔ 인계 항목 정의`가 M:N 관계가 되고, M:N 해소 테이블이 자연스럽게 생긴다.

### 환자 엔티티 처리 방침

인계는 결국 환자 단위라 엔티티를 피할 수 없다. **피하지 말고 설계로 답한다.**

- 식별정보를 **병상번호 + 환자코드**까지만 둔다. 이름·주민번호·연락처 없음
- 데모 데이터는 **전부 가상**임을 기술서에 명시
- **이 판단을 T6-b에 기록하면 그대로 "설계 상의 고민" 슬라이드가 된다** — 개인정보보호법 제23조를 근거로 들 수 있다

### 스코프 검증

| 항목 | A-lite | 판정 |
|---|---|---|
| Actor | 수간호사 / 간호사 = 2명 | ✅ |
| 화면 | 로그인, 병동 대시보드, 근무 등록, 역할 배정, 인계 항목 템플릿 관리, 결원 재배정, 변경 이력 / 내 근무·역할, 인계 작성, 인계 수신·확인, 내 인계 이력 = **11개** | ✅ |
| 엔티티 | user, ward, shift_assignment, role_type, zone, patient(최소 식별), handover, handover_item, role_item_template, handover_ack, reassignment_log = **11개** | △ 권장 상한이나 관계가 명확해 감당 가능 |
| 외부 연동 | 불필요 | ✅ |
| 배경 근거 | 관찰 + [C] 통계 | ✅ |

### Out of scope (5줄)

1. 근무표 **자동 생성** (B2B 레드오션 + NP-hard, solver 영역)
2. **실제 EMR 연동**
3. **실제 환자 개인정보** — 가상 데이터만 사용
4. **임상적 판단·추천** (중요도 자동 정렬, 위험 예측)
5. **교육 일정·급여·알람** — Appendix의 향후 확장

## 9. 다음에 확인할 것 — 인터뷰 질문

> ★ **1번이 가장 중요하다.** 이 답 하나가 후보 A-lite의 중복 여부와 화면 범위를 결정한다. Epic Art가 이미 환자 배정 제안을 하고 있으므로, 국내 EMR에도 비슷한 기능이 있다면 스코프를 다시 짜야 한다.

1. **현재 병원 EMR에 인수인계 기능 또는 담당환자 배정 기능이 이미 있는가?** 있다면 실제로 쓰는가, 안 쓴다면 왜?
2. **차지/액팅 배정은 언제, 누가, 어디에 적어서 공지되나?** (전날 저녁? 당일 아침? 화이트보드? 카톡?)
3. **인계할 때 실제로 무엇을 보고 말하나?** 차지와 액팅이 받는 내용이 어떻게 다른가?
4. **인계 누락으로 곤란했던 경험**이 구체적으로 어떤 거였나?
5. **누가 갑자기 못 나오면** 실제로 무슨 일이 일어나나? 연락 순서는?
6. **근무표는 언제 나오고**, 나온 뒤 한 달에 몇 번쯤 바뀌나?

> 2~3번 답이 화면 구성과 엔티티를 거의 그대로 결정한다. 4번은 배경 슬라이드의 인용문이 된다.

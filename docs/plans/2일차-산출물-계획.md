## B. T6 전 행 · 빈칸 0 (**2.5h** — 1.5h 에서 상향)

기능별 작업 API 에 더해 **조회·진입 API** 를 빠뜨리지 않는다. 코덱스가 짚은 누락:

| 누락 | 채울 행 |
|---|---|
| **F-04 수신자 요약 저장** ★차단 | `PATCH /handovers/{id}/receipt` (`receiver_summary`). confirmation 은 계속 별도 요청(body 없음) |
| **`received_at` 생성 동작** ★차단 | `POST /handovers/{id}/receipt` (화면 진입) **또는** T6-b 에 *"이번 범위에서 쓰지 않는다"* 사유 기록. `GET` 에 쓰기 부작용을 넣지 않는다 |
| **F-02 배정 보드 진입 조회** | `GET /wards/{id}/assignment-board?date=` — 날짜×근무조 · 근무자별 역할·팀 · 인계 담당 |
| **F-05 재배정 화면 진입 조회** | `GET /shift-assignments/{id}/reassignment-context` — 결원자 · 대체 후보 · **남은 인계 담당 N건** |
| **로그인(화면 1)** | 범위를 늘리지 않는다 → **T6-b 에 "외부 인증 가정 · API 명세 범위 밖"** 한 줄 |
| 그 외 | F-01 등록·목록 · F-04 작성/항목 저장/전달/상세 열람/이력 · F-05 결원 등록·대체자 배정·담당 이관·이력 · F-06 `GET/PUT` |

**`/me/shifts` 응답 보완** ★차단 — 현재 `handover_status` 는 *받는* 인계만 뜻해서 화면 8 의 버튼(작성/확인/열람)을 결정할 수 없다.
→ `incoming_handover_id`·`outgoing_handover_id` + 각 `status` 를 넣는다 (또는 서버 계산 `available_actions[]`).

**읽기 3단을 T6 에 판정식으로 박는다** ★차단 — 안 적으면 OAS 에서 사라진다. `GET /handovers/{id}` 행에 세 분기를 그대로:
① `HEAD_NURSE` + 병동 일치 ② `from`/`to` 당사자 ③ **같은 팀 · 같은 날·근무조 + `sent_at IS NOT NULL`**

- ③ 을 `status = SENT` 로 적으면 **`SUPERSEDED` 에서 권한이 깨진다** (DRAFT→SUPERSEDED 와 SENT→SUPERSEDED 가 구분 안 됨) → **`sent_at` 으로 판정**
- 팀 기반 읽기는 **`shift_assignment.status = ACTIVE`** 로 제한 (결원자 포함 여부를 명시)
- 버튼 권한은 **`is_handover_owner` 만** 쓴다. `role_name` 은 표시용 — DBML 이 역할·팀을 강제하지 않기로 했으므로 UI 가 `role_name=차지` 로 판정하면 충돌한다
- **`403/404` 를 `403` 으로 확정**하고 사유 한 줄을 T6-b 에 남긴다 (미결로 끌고 가지 않는다)
- **F-05 담당 이관은 쪼개지 않는다** — `SUPERSEDED` 처리 + 후속 인계 생성이 한 트랜잭션이다

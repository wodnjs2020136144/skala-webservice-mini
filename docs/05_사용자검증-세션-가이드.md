### 1-4. Q1 — 역할이 언제 정해지나

> **"차지/액팅 배정, 전날에 미리 정해져? 아니면 그날 환자 수 보고 정해져?"**

**답이 모호할 때 되묻기** (*"그때그때 달라"* 가 나오면)
> **"그럼 어제 퇴근할 때, 오늘 네가 뭐 할지 알고 갔어?"**

| 답 | 확정되는 것 |
|---|---|
| 전날에 나온다 | **분기 A(조기 공개)**. `8_myshift_nurse` 상단 = *"9/17 목 · N · 차지"* 로 확정 표시 |
| 당일 아침에 정해진다 | **분기 B(변경 전파)**. 상단 = *"역할 미정"* + 확정되면 보이는 구조 |
| 대충 전날, 당일에 바뀜 | **A + B 둘 다.** `shift_assignment.role_type_id` 가 nullable 인 현재 설계가 맞다는 뜻 |

> 세 번째가 가장 가능성이 높다. **그 경우 지금 DBML을 고칠 게 없다** — nullable 로 둔 판단이 근거를 얻는다.

## 2. 2일차 밤 (대면 30분)

### 2-0. ★ 시작 문구 — 동의부터 받는다 [v2 신설]

**과제를 주기 전에 이것부터 말한다.**

> **"내용은 메모만 하고 녹음은 안 할게.**
> **병원 이름이나 환자 얘기는 안 해도 돼.**
> **답변 일부를 이름 없이 발표자료에 인용해도 괜찮아?"**

- **직접 인용은 세션 마지막에 그 문장을 다시 보여주고 확인받는다.** 기억에 의존해 옮기지 않는다
- 인용 동의를 안 하면 **인용 없이 관찰 결과만** 쓴다. 그것만으로도 충분하다

### 2-1. 가기 전 준비 (2일차 오후)

- [ ] **DBML·YML은 가기 전에 끝낸다.** 세션 후에 설계를 새로 할 시간이 없다
- [ ] 목업 **8개 이상**을 브라우저 탭 순서대로 준비
- [ ] 기록용 노트 + **타이머**. 요약하지 말고 말한 그대로 받아적는다
- [ ] 시간 **30분**. 나이트 전날이거나 데이 다음날이면 더 짧게

### 2-2. 의견을 묻지 말고 과제를 준다

| ❌ | ✅ |
|---|---|
| "이 화면 괜찮아?" | **"내일 네가 뭘 맡는지 확인하려면 어디를 볼 것 같아?"** |
| "이 기능 필요할까?" | **"인계를 넘긴다고 치고, 여기서 뭘 먼저 할 것 같아?"** |
| "이 이름 이해돼?" | **"여기 적힌 게 무슨 뜻일 것 같아?"** |

의견을 물으면 칭찬만 돌아온다. 연인이면 더 그렇다.

### 2-3. 관찰 규칙 [v2 수정 — "5초" 규칙 폐기]

- 화면을 넘기기 전에 **과제부터 말하고, 입 다물고 본다**
- **최대 20~30초 관찰 → 그래도 막히면 표준 힌트 1회 제공 → 그 후 성공 여부도 기록**
  - 표준 힌트는 미리 정해 문장으로 준비한다 (매번 다른 힌트를 주면 데이터가 섞인다)
  - 예: *"이 화면 안에 있어. 천천히 봐도 돼."*
- **"설명이 필요했으면 그 화면은 실패"는 과했다.** 힌트 후 성공했는지가 더 유용한 데이터다
- 막힌 지점, 잘못 누른 곳, 머뭇거린 곳을 전부 기록한다

### 2-4. 과제 5개

1. "내일 네가 **무슨 근무에 무슨 역할**인지 확인해봐"
2. "**우리 팀 환자가 누구누구**인지 봐봐"
3. "지금 **인계를 넘긴다**고 치고 작성해봐"
4. **"인계를 받았다고 생각하고, 핵심 내용을 네 말로 짧게 정리한 다음 확인 처리해봐"** [v2 수정]
   - 초안은 *"받았다고 처리해봐"* 였다. 그러면 **단순 ack만 검증되고 `receiver_summary` 는 검증되지 않는다.**
   - I-PASS의 `Synthesis by receiver` 를 근거로 쓰는 이상, **요약 입력까지 시켜야** 그 근거가 검증된다
5. (수간호사 화면) **참여자의 경험에 따라 갈린다** [v2 수정]
   - **수간호사·책임간호사 경험이 있으면** → 과제 기반: *"한 명이 못 나온다고 하면 여기서 뭘 할 것 같아?"*
   - **경험이 없으면** → 탐색 질문으로 전환: *"실제로 누가 못 나오면 수간호사가 어떻게 처리하는지 본 적 있어?"*
   - 어느 쪽이든 **발표에는 `간호사 화면 = 검증 1명 / 수간호사 화면 = 가설` 로 구분해 적는다**

### 2-4b. ★ 가치 검증 질문 3개 [v5 신설]

**과제(2-4)는 "쓸 수 있는가"를 본다. 이 셋은 "문제를 줄이는가"를 본다. 다른 일이다.**
조작이 매끄러워도 **안 쓸 이유**가 있으면 서비스가 성립하지 않는다.

> **V1 과 V2 를 합쳐서 판정하지 않는다.** 서로 다른 사람의, 서로 다른 부담이다.

**V1. 인계 메모를 여기로 옮길 수 있는가 ★ 가장 먼저 묻는다** [09-16 문구 교체]

> **"지금 인계 메모는 어디에 적어? 그걸 이 화면으로 옮겨서 적는 거라면 쓸 것 같아?"**

- **공식 의무기록은 EMR 이 맡고, 교대 인계 메모는 그와 분리되어 관리된다** `[C 발언 재해석 — 원문 재확인 예정]`.
  우리 서비스는 **그 인계 메모 계층을 대체**한다 → **대체가 성립하면 이중 입력이 아니다**
- **부정이면 대체가 아니라 병행**이라는 뜻이고, 그때 **차지가 같은 내용을 두 번 쓴다**
  → **F-04 의 "새 인계 작성" 전제를 다시 본다.** 설계의 뿌리가 걸린 질문이다
- 되묻기: *"의무기록은 그대로 두고, 인계 메모만 여기로 옮기는 거야."* / *"그럼 어떻게 하면 쓸 것 같아?"*
- 함께 확인 — **원발언 재확인**: *"어제 말한 '하나의 전산 화면' 이, 의무기록이랑 인계 메모가 같은 화면이라는 뜻이었어, 아니면 인계 메모를 그 화면에서 적는다는 뜻이었어?"*
- ⚠️ **09-16 이전 문구 철회** — *"EMR 에 적은 인계 내용을 9번 화면에도 다시 적어야 한다면"* 은 **전제가 틀렸다**
- ✅ **답이 늦어도 설계는 진행한다** — V1 이 가르는 것은 **분리 여부가 아니라 대체냐 병행이냐**이고,

- **환자나 사건의 구체적 임상 내용은 받지 않는다. 역할·처리 흐름만.**

#### ★ 반증이 나왔을 때 — "주제를 바꾸지 않는다"는 철회한다 [v3 수정]

v2는 *"무엇이 나와도 주제를 바꾸지 않는다"* 고 썼다. **이건 세션에서 반증이 나올 수 없게 만드는 문장이다.**
검증 세션인데 결과가 설계를 바꿀 수 없다면 검증이 아니다.

**정확한 사실은 이것이다.**

- **3일차 오전에 주제를 바꾸는 것은 물리적으로 불가능하다.** 4시간이고 산출물 3종이 이미 만들어져 있다
- **그러나 그것이 "반증이 일어날 수 없다"는 뜻은 아니다.** 반증이 나오면 **산출물은 그대로 내되, 기술서와 발표에 그 반증을 정직하게 적는다**

> *"검증 결과 전제 X가 성립하지 않는 것으로 확인되었다. 이에 따라 ○○를 이렇게 재해석했고, △△는 향후 과제로 남긴다."*

**이 서술은 감점이 아니라 설계 역량의 증거다.** 검증해놓고 결과를 숨기는 것이 감점이다.

- 그리고 **진짜 반증 지점은 2일차 밤이 아니라 오늘 밤이다.** Q2-a·b·c에서 x2가 나오면 **2일차 아침에 바꿀 시간이 있다.** 오늘 밤 질문을 대충 하지 않는 이유가 이것이다
- x1은 확률이 낮다 — **불편 5번은 이미 직접 관찰한 내용**이기 때문이다. 다만 **"관찰했으니 맞다"도 1명의 관찰이다**

## 4. 이 세션을 발표에 쓰는 법

세부 평가 기준의 **"구체적인 문제 정의(원인·배경·현황 포함)"** 와 **"화면 흐름이 자연스러운가"** 를 동시에 친다.

### 표현은 정확하게 [v2 수정]

| ❌ 쓰지 말 것 | ✅ 이렇게 |
|---|---|
| "사용자 검증 완료" | **"현직 간호사 1명 대상 탐색적 과제 기반 사용성 확인 (편의표본)"** |
| "간호사들은 ~라고 한다" | **"참여자는 ~라고 말했다"** |
| (수간호사 화면도 검증한 것처럼) | **"간호사 화면 = 검증 / 수간호사 화면 = 가설"** |

### 슬라이드 한 장

> **탐색적 사용성 확인 1회** (현직 간호사 1명, 대면 30분, 과제 5개)
> 무도움 성공 N / 힌트 후 성공 M / 실패 K
> 반영 — 즉시 A건, 판단 후 B건 / 향후 과제 C건 / **전제 재검토 X건**

- **막힌 지점을 숨기지 않는다.** *"3번 과제에서 버튼을 못 찾아 라벨을 바꿨다"* 는 문장이 **설계를 검증했다는 증거**다
- 배경 슬라이드에는 **동의받은 인용문**을 쓴다. *"~라고 한다"* 보다 훨씬 강하다

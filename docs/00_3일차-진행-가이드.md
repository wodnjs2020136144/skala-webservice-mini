## 2. 3일 내내 유지할 척추 문서 — 화면·API·데이터 매핑표 [전략]

세 산출물(기술서 PDF / API.yml / DB.dbml)을 따로 쓰면 어긋난다. **표 한 장을 단일 출처로 두고 세 파일을 파생**시킨다. (템플릿 `docs/02_작업-템플릿.md` T6)

```
기능ID | 화면ID | Actor | 트리거 | Method | 경로 | 요청 | 응답 필드 | 데이터 근거 | 예외(코드)
```

**표의 4가지 규칙 — 기본은 지키고, 예외는 사유를 한 줄 적는다**

1. 화면에 **보이는 모든 값**은 어느 API의 응답 필드에 존재한다.
2. 응답 필드의 모든 값은 **테이블 컬럼**이거나 `서버 계산`으로 표시된다.
3. 기능 목록의 **모든 기능 ID**는 최소 한 행에 등장한다. ← 이 규칙 때문에 표에 `기능ID` 열이 필요하다
4. 표에 한 번도 안 나오는 API·테이블·컬럼은 **삭제하거나, 남기는 이유를 T6-b에 기록**한다.

> ⚠️ 4번의 정당한 예외: 감사 로그, 이력 스냅샷(주문 시점 가격처럼 **그때의 값**을 보존해야 하는 것), 내부 FK, `created_at`/`updated_at`, 성능용 비정규화.
> **이 예외를 기록해 두면 그대로 '설계 고민' 슬라이드 재료가 된다.** 지우는 것보다 점수가 높다.

### 블록 A. 데이터 모델 1차 — **화면에서 역산** (90분) [전략]

- **DB를 먼저 그리지 않는다.** 목업 캡처를 펼쳐놓고 화면에 보이는 값을 전부 나열 → 같은 주어끼리 묶기 → 엔티티

- **원칙**: 파생값은 컬럼으로 만들지 않고 `서버 계산`으로 표시한다 [권장]
- **예외를 인정한다**: 그 시점의 값을 보존해야 하는 이력 스냅샷, 재계산 비용이 큰 집계값, 감사 대상 값은 컬럼으로 둘 수 있다.
  **단 T6-b에 "왜 컬럼으로 뒀는지" 한 줄을 남긴다.** 무판단으로 둔 것과 판단해서 둔 것은 다르게 읽힌다

### 블록 B. API 목록 1차 (90분)

- 매핑표의 `Method·경로` 열을 채운다. 단위는 **화면 진입 시 / 버튼 클릭 시**
- 경로는 **리소스 중심**, 동작은 HTTP Method로 [필수 — "적절한 HTTP Method"]
- **대시보드처럼 여러 리소스를 합치는 화면은 전용 조회 API를 두는 편이 낫다** [권장]
  - 다만 전용 API가 늘면 재사용성이 떨어진다. **기본은 리소스 API, 화면이 3개 이상 리소스를 합칠 때만 전용 API**로 판단하고 그 기준을 적어둔다 [전략]

### 09:00–10:15 · 정합성 대조 ★ 가장 점수가 큰 시간

**(1) 존재 대조 — 세 방향으로 각각 훑는다**

- **UI → API**: 화면의 모든 버튼·데이터에 대응 API가 있는가 → 없으면 API 추가
- **API → DB**: 응답 필드마다 컬럼 또는 `서버 계산` 근거가 있는가 → 없으면 컬럼 추가
- **DB → UI**: 어느 화면에서도 안 쓰이는 테이블·컬럼이 있는가 → 삭제하거나 **T6-b에 사유 기록**

**(2) 정상 흐름 밖 점검 — 리뷰 반영으로 신설** [필수 근거: 에러 코드 정의 / 예외 시나리오 가점]

- **권한**: Actor가 허용되지 않은 API를 호출하면? → `401`(미인증) vs `403`(권한 없음) 구분이 되어 있는가
- **경계값**: 빈 목록 / 중복 생성 / 존재하지 않는 ID → `200`(빈 배열) `409` `404` 가 정의돼 있는가
- **상태 전이**: 상태 변경이 **가능한 순서와 금지되는 순서**가 정의돼 있는가 (예: `완료 → 대기` 역행 금지)

> 에이전트 활용 최적 지점: 매핑표 + YML + DBML을 통째로 주고 **"불일치만 찾아라, 고치지 마라"**.

## 6. 흔한 실패 5가지

1. **주제가 커서 화면을 다 못 그린다** → 1일차 오전 Out of scope로 차단
2. **DB를 먼저 그리고 화면을 끼워 맞춘다** → `화면 → 필드 → 엔티티` 순서 고정
3. **세 산출물을 따로 쓴다** → 매핑표 단일 출처에서 파생
4. **3일차에 PDF를 처음 조립한다** → 1일차 골격 + 산출 즉시 삽입으로 차단 ← **리뷰가 잡아낸 최대 위험**
5. **UI 흐름도 누락 / 파일명 오류** → 배점이 통째로 날아간다

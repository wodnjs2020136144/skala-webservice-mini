## 2. 3일 내내 유지할 척추 문서 — 화면·API·데이터 매핑표

세 산출물(기술서 PDF / API.yml / DB.dbml)을 **따로 쓰면 반드시 어긋난다.** 어긋남은 곧 감점이다.
그래서 **표 한 장을 단일 출처로 두고 세 파일을 거기서 파생**시킨다. (템플릿: `docs/02_작업-템플릿.md`)

| 화면ID | 화면명 | Actor | 사용자 행동(트리거) | 호출 API | 요청 | 응답 필드 | 사용 테이블·컬럼 | 예외 |
|---|---|---|---|---|---|---|---|---|

**표의 4가지 불변 규칙**

1. 화면에 **보이는 모든 값**은 어느 API의 응답 필드에 존재한다.
2. 응답 필드의 모든 값은 **테이블 컬럼**이거나 `서버 계산`으로 표시된다.
3. 기능 목록의 **모든 기능 ID**는 최소 한 행에 등장한다.
4. 표에 한 번도 안 나오는 **API·테이블·컬럼은 삭제**한다. (쓰이지 않는 설계는 불일치로 읽힌다)

## 3. 1일차 (오늘, 9/15) — 기획을 끝낸다

### 블록 A. 주제 확정 & 스코프 고정 (60~90분) ★ 오늘 가장 중요한 시간

이미 후보 주제가 있으므로 **새로 찾지 말고 아래 6문항으로 검증**한다. 하나라도 걸리면 좁힌다.

1. **한 문장**이 써지는가 — "*누가 / 어떤 상황에서 / 무엇이 불편해서 / 무엇을 할 수 있게 된다*"
2. 배경에 **근거·현황**을 쓸 수 있는가 (직접 겪었거나 관찰한 문제인가). 상상으로 만든 문제는 배경 슬라이드가 비어버린다.
3. **Actor가 2~3명**으로 끝나는가 — 4명 이상이면 3일에 화면을 못 채운다.
4. **화면 10~13개**로 전체 기능이 커버되는가.
5. 핵심 엔티티가 **6~9개**인가.
6. 외부 연동(결제·지도·실시간 스트리밍 등)이 **필수가 아닌가** — 필수면 스코프 밖으로 뺀다.

**이 블록의 산출물 3개**

- 서비스 한 문장 정의
- Pain point 3개 ↔ Solution 3개 (Actor를 붙여서)
- **하지 않는 것(Out of scope) 5줄** ← 이게 없으면 3일 내내 스코프가 번진다

### 블록 B. Actor·기능 정의 (60분)

- Actor 표: `Actor 구분 | 역할·권한 | 상세 제공 기능`
- 기능마다 **F-01, F-02… ID를 부여**한다. 이후 화면·API·테이블이 전부 이 ID를 참조한다.
- **완료 판정**: 모든 Pain point가 최소 1개 기능으로 해결되고, 모든 기능이 Actor 1명 이상에 붙는다.

### 블록 C. 화면 목록 + 전체 UI 흐름도 (90분)

- 화면 ID를 **파일명 규칙으로** 부여한다: `1_login_main`, `2_dashboard_student`, `3_course_home_student` …
  → 흐름도 노드, 목업 파일, 기술서 슬라이드가 같은 ID로 묶인다.
- 흐름도는 **Actor별 레인**으로 나눈 노드 그래프 1장. 로그인이 공통 진입점.
- **완료 판정**: 기능 ID가 전부 화면 하나 이상에 매핑된다. 매핑 안 되는 기능은 기능에서 빼거나 화면을 추가한다.

### 블록 D. 화면 목업 착수 (남은 시간 전부)

- 우선순위: **로그인 → Actor별 대시보드 → 핵심 트랜잭션 화면(등록/제출) → 목록·상세 → 관리자**

- 목업 **코딩은 에이전트에 위임해도 된다.** 단 화면에 무엇이 들어가는지는 직접 정한 뒤 지시한다.

## 4. 2일차 (9/16) — 설계를 끝낸다

> 커리큘럼: 시스템 설계 · 데이터 모델 작성 · API 명세 작성 · 17:20 조별 대표 선정

### 블록 A. 데이터 모델 1차 — **화면에서 역산** (90분)

- **DB를 먼저 그리지 않는다.** 목업 캡처를 펼쳐놓고 화면에 보이는 값을 전부 나열 → 같은 주어끼리 묶기 → 엔티티.
- 나열한 값은 셋 중 하나로 분류한다:
  1. **저장 컬럼**
  2. **파생값** (다른 컬럼 + 현재 시각으로 계산) → **컬럼으로 만들지 않고 `서버 계산`으로 표시**
  3. **상수/Enum**
- 파생값을 컬럼으로 만들지 않는 판단이 정규화 의식으로 읽힌다. (참고자료의 `수강 상태`, `지각 제출 여부` 처리 방식)

### 블록 B. API 목록 1차 (90분)

- 매핑표의 `호출 API` 열을 채운다. 단위는 **화면 진입 시 / 버튼 클릭 시**.
- 경로는 **리소스 중심**, 동사는 HTTP Method로. (`/activities/{id}/submissions` + `GET/POST/PUT/DELETE`)
- **화면 전용 조회 API를 두려워하지 말 것.** 대시보드처럼 여러 리소스를 합쳐 보여주는 화면은 전용 API가 정답이다.
  (참고자료: `/activities/pending`, `/submissions/recent`, `/activities/pending-grades`)

### 블록 C. DBML 완성 (2~2.5시간)

작성 규칙 — 아래 8개를 전부 지킨다.

1. **Enum 분리 선언** — 상태값·유형값은 varchar가 아니라 Enum으로.
2. 모든 테이블에 **PK 명시**, 관계는 파일 하단에 **`Ref:` 블록으로 모아서** 선언.
3. **M:N은 연결 테이블로 해소** + `(a_id, b_id) [unique]` 인덱스로 중복 방지.
4. 타입을 구체적으로: `varchar`, `integer`, `decimal(5,2)`, `timestamp`, `date`, `boolean`, `text`.
5. `not null`, `default`, `increment` 제약을 빠짐없이.
6. **모든 컬럼에 `note`** — 무엇을 담는지 / 계산 규칙 / 어느 화면에서 쓰는지.
7. 섹션 주석(`// ====`)으로 Core / 관계 / 트랜잭션 그룹을 나눈다.
8. 파생값·정책은 **테이블 위 주석 블록**으로 설명한다 (왜 컬럼으로 두지 않았는지).

- **검증**: [dbdiagram.io](https://dbdiagram.io) 에 붙여넣어 ① 에러 0 ② 관계선이 의도대로인지 눈으로 확인 → 이 화면이 그대로 기술서의 ERD 캡처가 된다.

### 블록 D. OAS(YAML) 착수 (2시간)

**순서가 중요하다. `components`를 먼저 쓰고 `paths`를 나중에 쓴다.** 반대로 하면 중복 지옥이 된다.

1. `components/schemas` — 엔티티별 응답 스키마 + **목록 래퍼**(`PagedResponse`) + `Error`
2. `components/responses` — `BadRequest(400)`, `Unauthorized(401)`, `Forbidden(403)`, `NotFound(404)`
3. `components/parameters` — `PageParam`, `SizeParam` 등 반복 파라미터
4. `tags` — Actor/도메인별 그룹 (Swagger UI에서 묶여 보인다)
5. `paths` — 매핑표 **순서대로**. 각 오퍼레이션에 `summary`, `description`, 요청, `200/201`, 에러는 `$ref`

- **Security Schemes는 평가 제외**다. JWT 스키마 정의에 시간 쓰지 말고, 인증 방식은 `info.description`에 한 줄로 적는다.
- **검증**: [editor.swagger.io](https://editor.swagger.io) 에 붙여넣어 에러 0 + 렌더 확인 → 이 화면이 기술서의 API 캡처가 된다.

### 09:00–10:00 · 정합성 3중 대조 ★ 3일차에서 가장 점수가 큰 1시간

세 방향으로 **각각** 훑는다. 한 방향만 보면 반드시 놓친다.

- **UI → API**: 화면의 모든 버튼·데이터에 대응 API가 있는가 → 없으면 API 추가
- **API → DB**: 응답 필드마다 컬럼 또는 `서버 계산` 근거가 있는가 → 없으면 컬럼 추가
- **DB → UI**: 어떤 화면에서도 안 쓰이는 테이블·컬럼이 있는가 → 삭제하거나 화면 추가

> 에이전트 활용 최적 지점: 매핑표 + YML + DBML을 통째로 주고 **"불일치만 찾아라, 고치지 마라"**.

## 6. 흔한 실패 5가지

1. **주제가 커서 화면을 다 못 그린다** → 1일차 오전에 Out of scope 확정으로 차단
2. **DB를 먼저 그리고 화면을 끼워 맞춘다** → `화면 → 필드 → 엔티티` 순서 고정
3. **세 산출물을 따로 쓴다** → 매핑표 단일 출처에서 파생
4. **UI 흐름도 누락 / 파일명 오류** → 30점 또는 20점이 통째로 날아간다
5. **3일차 오전에 기능을 추가한다** → 3일차는 **추가 금지, 정합성만**

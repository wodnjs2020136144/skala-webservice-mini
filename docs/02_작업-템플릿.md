## T6. ★ 화면·API·데이터 매핑표 (단일 출처)

| 화면ID | 트리거(진입/버튼) | Method | 경로 | 요청 (path·query·body) | 응답 필드 | 사용 테이블·컬럼 | 예외(코드) |
|---|---|---|---|---|---|---|---|
| | 화면 진입 | GET | | | | | 401 |
| | 저장 클릭 | POST | | | | | 400, 409 |

**4가지 불변 규칙**

1. 화면에 보이는 모든 값 → 어느 행의 응답 필드에 존재
2. 응답 필드의 모든 값 → 테이블 컬럼이거나 `서버 계산`
3. 모든 기능 ID → 최소 1행에 등장
4. 표에 없는 API·테이블·컬럼 → 삭제

### DBML 작성 규칙 체크

- [ ] 상태·유형값은 전부 `Enum`으로 분리 선언
- [ ] 모든 테이블 PK 명시 / `Ref:` 블록을 파일 하단에 모음
- [ ] M:N은 연결 테이블 + `(a_id, b_id) [unique]`
- [ ] 타입 구체화 (`varchar`/`integer`/`decimal(5,2)`/`timestamp`/`date`/`boolean`/`text`)
- [ ] `not null` / `default` / `increment` 명시
- [ ] **모든 컬럼에 `note`** (담는 값 / 계산 규칙 / 사용 화면)
- [ ] 섹션 주석으로 그룹핑
- [ ] 파생값을 컬럼으로 두지 않은 이유를 주석 블록으로 설명
- [ ] dbdiagram.io 렌더 에러 0 + 관계선 육안 확인

## T8. OAS 작성 순서

1. `openapi: 3.0.3` + `info` (인증 방식은 여기 description에 한 줄)
2. `servers`
3. `tags` — Actor/도메인 그룹
4. `components/schemas` — 엔티티 응답 스키마 + `PagedResponse` + `Error`
5. `components/responses` — `BadRequest` / `Unauthorized` / `Forbidden` / `NotFound`
6. `components/parameters` — `PageParam` / `SizeParam` 등
7. `paths` — T6 표 순서대로

### API 작성 규칙 체크

- [ ] 경로는 리소스 중심, 동작은 HTTP Method로
- [ ] 목록 조회 / 단건 조회 / 생성 / 수정 / 삭제가 필요한 리소스마다 갖춰짐
- [ ] **대시보드·요약 화면용 전용 조회 API**가 있음
- [ ] 모든 오퍼레이션에 `summary` + `description`
- [ ] 성공 응답(200/201) + 에러 응답이 `$ref`로 연결
- [ ] 공통 스키마 재사용 (`$ref`)으로 중복 없음
- [ ] Security Schemes는 **작성하지 않음** (평가 제외)
- [ ] editor.swagger.io 렌더 에러 0
